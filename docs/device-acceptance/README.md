# 真机验收留档

> **每一次真机验收在这里按版本留一份记录。**
>
> 为什么单独开一个目录，而不是写在 `docs/INCIDENTS.md` 里：
> `INCIDENTS.md` 记的是**出了什么错**（失败与教训），
> 这里记的是**什么被证明成立了**（成功与证据）。两者混在一起时，
> 「到底验过什么」会淹没在事故细节里 —— 而**验收记录的用途正是回答那个问题**。

## 每份记录的格式

```markdown
# v<版本> 阶段 <N> 真机验收

- 设备：<型号 / Android 版本 / SDK>
- 产物：<APK 摘要 sha256 / 字节数>
- 提交：<git commit>
- 验收时间：<日期>

| # | 验收标准 | 结论 | 证据（可复现） |
|---|---|---|---|
| 1 | … | ✅ / ❌ / **未验证** | 命令 + 输出 / 截图路径 |

## 未验证的项（如实列出）
## 与记录的偏差
```

## 硬规矩

1. **没有实际执行的，写「未验证」，不写「通过」。**
2. **每一条结论都要给可复现的证据** —— 命令 + 输出，或者 `docs/evidence/` 下的截图。
   「我看了一眼界面」不是证据；界面会自述（第 14 条就是被界面自述骗过一次）。
3. **状态结论必须有独立证据** —— 进程 uid、端口 owner、浏览器 ESTABLISHED 连接，
   而不是应用自己显示的那一行字。
4. **失败也要留档。** 一次没有验收通过的记录，比一次「反正后来好了」有价值得多。
